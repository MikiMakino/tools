# 官報公告確認 0.7：実装と検証

2026年9月29日。Windows版のソースを更新しました。今回、配布ZIP・EXEの新規作成、Minicondaや追加パッケージのインストールは行っていません。GitHubへの配置対象は `MikiMakino/tools` の `kanpo2` で、ソース・手順書・テスト・架空サンプルのみです。

## 今回の操作の流れ

1. 取引先台帳を読み込み、「当日分を取得（1日1回）」で号を選ぶか、手元のPDFを選択して処理を開始します。
2. 原文PDFを保存してから、号ごとの公告開始位置を探し、暫定範囲の文字読取と照合を進めます。
3. 処理中に人の範囲確認や文字修正を求めません。失敗・範囲不明を記録し、処理可能な残りを進めます。
4. 終了後、「確認待ち」の一覧から公告範囲と各ページを確認します。人が範囲を確定するまで、そのページを確認済みにはできません。
5. 「印を原文と確認」で要確認箇所を確認できます。位置が分からない場合はページ全体の指摘になります。必要なら紙面を囲んで部分的に再読取します。

機械の処理結果と人の確認状態は別です。OCRが文字を返しても、人の確認済みにはしません。部分的な再読取だけが成功した場合も、ページ全体の失敗・未処理を成功に変えません。

## 保存と繰り返し実行

- 通常の原文保存先は `%LOCALAPPDATA%\KanpoChecker\pdf`。評価用起動は `%LOCALAPPDATA%\KanpoChecker-Evaluation\pdf` です。「保存先を開く」から開けます。
- 原文は内容のハッシュを確認して保存し、OCRや赤枠で書き換えません。赤枠は確認用画像の上への表示です。
- 中断後は保存PDFから再開できます。既に成功したページは通常の再開では読み飛ばし、ページを選んだ強制再OCRもできます。
- 手動PDF取り込み、台帳読み込み、再OCR、部分再読取、再照合には日次の回数制限を設けていません。
- 取得ボタンは日本時間の当日分を対象とし、同じ保存先ではPDF取得の開始を1日1回に制限します。失敗・中断・再起動でも記録を保持します。追加号や再取得は手動対応です。
- 取得状態とOCR状態は別に保存します。「取得済み」は選択した対象PDFが保存された意味で、当日の全発行号の網羅や読取の完了を意味しません。

利用者が開始する当日1回のモードでは、robots.txtの除外指定を注意として表示し、当日の一覧に掲載された選択号の取得を進めます。HTTP 403・429などの拒否では後続を停止します。公開一覧にないURL、別号への転送、日付変更後の後続取得、同じ号の再試行は認めません。

## 検証したこと

日次取得の追加修正後、自動テスト230件はすべて成功しました。原本先行保存、ページ・文書の失敗継続、中断と再開、日次取得記録、確認状態と履歴、近似候補、CSV、既存データの移行に加え、当日公開一覧にある号だけの取得、別号転送の拒否、HTTP 403・429での停止、完全受信直後の中止でも原本を保持することを確認しています。EXEビルドの工程テストは模擬処理で、実EXEの作成・起動は行っていません。

2026年9月29日16時36分（日本時間）に、公式サイトの当日分4号を実ダウンロードしました。本紙1797号32ページ、号外214号72ページ、政府調達179号40ページ、特別号外53号2ページの計146ページです。4号とも読めるPDFとして保存され、受信時と保存後のハッシュが一致しました。DBを閉じて開き直した後の2回目は、ダウンロード処理を呼ばずに拒否しました。この実通信試験はOCR無効で実施し、範囲未判定・確認必要として原本を保持しています。OCR精度や1号全体の実OCR通し確認が完了したという意味ではありません。

実際の画面でも、複数PDFの処理中に確認ダイアログを出さないこと、範囲未確定から人の確認済みへ進む順序、原文画像への印、部分再読取の本文保存、範囲不明PDFのCSV出力、再起動後の保持を確認しました。照合は背景で処理し、画面の再表示には前回結果を再利用します。

日次取得画面は、実際のTk画面と模擬通信・模擬OCRで2号の選択、背景取得、原本を先に保存、処理中の追加確認なし、再起動後の取得ボタンの制限を確認しました。実サイトへの通信試験とは別の試験です。
