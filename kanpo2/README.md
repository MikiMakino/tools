# 官報公告確認アプリ Windows版 0.7

官報PDFを先に保存し、公告範囲の候補探索、文字の読み取り、台帳との照合まで進めてから、人が原文を確認する社内向けアプリです。会社公告だけでなく、裁判所の破産・相続関係、官庁、特殊法人等、地方公共団体、政府調達などの公告を対象にできます。Windows 11 x64、1台・担当者1人での利用を想定しています。

このフォルダーは社内PC用のソース作成セットです。**今回の0.7はソース更新のみで、ZIP・EXEは新しく作成していません。実EXEの起動は未検証です。** 承認済みMinicondaがある社内PCでのビルドと実台帳による評価が残っています。同じフォルダーに `KanpoChecker.exe` がある完成後の配布物を読む場合は、作成手順を飛ばして `run_evaluation.bat` から起動してください。

GitHubの `MikiMakino/tools` リポジトリでは、この一式を `kanpo2` フォルダーに配置します。実台帳、実官報PDF、保存データベース、EXE、ZIPは含めません。社内PCへファイル内容をコピーする場合も、`sample` と `tests` を含むフォルダー構成を保ってください。

## 最初に行う操作

1. 「取引先台帳を読み込む」で、社内に置いた台帳のコピーを読み込みます。台帳がなくてもPDFの保存と読み取りはできます。
2. 「当日分を取得（1日1回）」で公開一覧を確認し、取得する号を選択します。手元のPDFは「保存PDFを取り込む」で複数選択できます。選択した原文を先に保存し、その後に公告探索・OCR・照合を進めます。処理中に公告範囲の確認操作は要求しません。
3. 終了後、確認待ち一覧を見ます。「全体」の行に範囲不明や文書処理の失敗があれば、「公告範囲を確認」で原文と対象ページを確認します。
4. 各ページの「印を原文と確認」で、赤枠の理由と原文を比べます。必要なら紙面をドラッグして部分を選び、「選択範囲を再読取」を行います。印のない箇所も正しく読めた保証はありません。
5. 公告の内容を確認してから、確認状態とメモを保存します。最後にCSV出力と全データのバックアップを行います。

中断後は「保存PDFの処理を再開」を使用します。文書やページを選択しているときはそのPDFだけ、選択していないときは全PDFを処理します。読み取り失敗・文字なし・未処理のページを再処理し、成功済みのページは通常の再開では読み飛ばします。成功したページを読み直す場合は、そのページを選んで「OCR再実行」を使用します。保存PDFの処理再開、再OCR、局所再読取、再照合には、1日1回の取得制限は適用しません。

## 別々に確認する状態

| 状態 | 意味 |
| --- | --- |
| 取得状態 | 未取得・取得失敗・一部取得・取得済み。原本PDFを保存できたかを示します。 |
| 公告範囲 | 未判定・候補で未確定・人が確認済み・公告対象なし。自動候補だけで人の確認済みにはしません。 |
| 読み取り処理 | 保存のみ・処理中・完了・確認必要・中断・失敗。OCRの成功は文字が正確なことの証明ではありません。 |
| 人の確認状態 | 未確認・要確認・確認済み。原文を見た人が保存する状態です。 |

取得済みでも、公告範囲や本文の確認が残る場合があります。処理完了でも人の確認は残ります。候補なしを「掲載なし」と確定しません。範囲不明や失敗でページを作れないPDFも文書として一覧に残し、CSVに文書全体の要確認行を出力します。

## 当日分の取得

「当日分を取得（1日1回）」は、日本時間の当日分の公開一覧を確認し、選択した号をまとめて取得する操作です。利用者が開始する方式で、時刻指定の無人実行やWindowsへの定期実行登録は行いません。

- PDF取得の開始を保存先のデータベースに記録し、同じ保存先では再起動後も1日1回に制限します。途中失敗・中止でも、その日の再取得はしません。公開一覧の確認だけでは取得開始の記録は付きません。
- 取得開始時刻を日本時間で表示し、一覧から選択した号の結果を残します。後から追加された号、未取得分、過去の号はブラウザで保存して手動で取り込んでください。
- 選択した号の原本保存を先に終え、その後に保存した文書を順番に処理します。同じ取得元の保存済み原本は内容のハッシュを確認し、再ダウンロードせず使います。
- 一部の取得失敗では残りを続行します。サイトの拒否、取得制限、中止など、全体停止が必要な場合は後続の取得を止めます。保存済み原本と処理結果は保持します。
- 原本登録に失敗した受信PDFは、保存先の `download_staging` に残して手動対応を求めます。原本保存に成功してから受信用の一時ファイルを消します。
- 1回の上限は40件です。通信は逐次行い、3秒以上、またはサイトが指定した長い間隔を空けます。公式の同一ホスト・HTTPSの公開実リンクだけを使用します。

2026年9月29日に、当日分4号・計146ページの公式PDFを実際に取得・保存し、再起動後の二重取得防止を確認しました。`robots.txt` のクロール除外指定は注意表示として残し、利用者が開始する当日1回のモードでは、それだけを理由に一律停止しません。HTTP 403・429の拒否応答では後続取得を止め、再試行しません。TLS証明書の検証、同じ公式ホストへの接続、選択号・ページ範囲の一致確認は維持しています。詳しい条件と実測結果は「自動取得の確認結果.md」に記載しています。

## 公告範囲と本文の読み取り

公告開始は、先頭ページから順に文字と紙面の見出し位置を確認して探します。4方向のOCRを使い、独立した「公告」と近くの節見出しを手掛かりにします。一部の文字しか読めない場合は、近くの「諸事項」と独立した公告タイトルも必要とし、弱い候補であることを表示します。日付・号数・ファイル名・固定ページ番号を開始条件には使いません。

開始候補が得られた場合は、そのページから末尾までを暫定対象として読み取りを進めます。目次と本文が同居するページなど、判断できないときは範囲不明として残します。処理後に人が「公告範囲を確認」で確定してください。人が確定した範囲を自動候補で上書きしません。公告と別の記事が同じページにある場合はページ全体が照合対象になるため、候補が公告に属するか原文を確認してください。

画像本文はWindows標準の日本語OCRをローカルで使用します。0.7では通常方向の読み取りに加え、別方向で読める会社名や公告タイトルなどを補足し、読み取り差・社名付近の不自然な文字・台帳名に似た読み取りなどを要確認の印として残します。必要な箇所では回数を限って領域を再OCRします。台帳名へ自動訂正せず、最初の読み取りと未確認の補足を比較できるよう保存します。

赤枠や要確認理由は誤読を調べる手掛かりです。誤読を全件発見する仕組みでも、信頼度の保証でもありません。類似した社名の候補は別会社の可能性があり、原文による確認が必要です。位置が分からない指摘はページ全体を確認します。局所再読取では4方向、または0・90・180・270度から向きを選べます。結果は未確認の補足として保存し、自動で人の確認済みにはしません。

原文PDF全体は改変せず保持します。パスワード入力なしで閲覧できる公開PDFの暗号化には対応しますが、閲覧パスワードが必要なPDFは拒否します。必要な場合だけ対象ページの描画用一時コピーを作り、処理終了後に削除します。画面の確認用画像では注釈などを省く場合があります。電子署名・注釈の確認は「原文PDF」から原本を開いて行ってください。このアプリは電子署名を検証しません。

## 台帳と確認履歴

台帳はCSV（UTF-8またはCP932）とExcel `.xlsx` の先頭シートに対応します。列は `取引先コード,会社名,住所` で、住所は任意です。取引先コードは文字列として先頭ゼロを保持してください。数値として失われたゼロは復元しません。サンプル台帳の会社と住所は架空です。

全行を検証してから台帳を差し替えます。差し替え後は対象ページが未確認に戻り、過去の確認は履歴に残ります。台帳名に似た読み取りの印と候補は、画面・CSVとも最新の台帳で再計算します。再OCRでも以前のメモと確認履歴を保持し、結果を要確認に戻します。失敗時に既存OCR本文を空の結果で消しません。照合はページ単位で、社名と住所が同じ公告に属することや同一法人であることは自動確定しません。

## 承認済みMinicondaでの準備と起動

社内承認済みの64ビットPython 3.12環境を使います。必要なものはTk、pypdf、cryptography、openpyxl、およびWindows標準の日本語OCRです。EXE作成にはPyInstallerも必要です。pip、未承認の配布元追加、外部インストールスクリプト、実行ポリシー変更は行いません。

社内で設定された配布元を使用し、必要に応じて環境管理担当者に `environment.yml` を渡してください。承認済み環境を用意する場合の例です。

```bat
conda env create -f environment.yml
conda activate kanpo-build
python check_environment.py --build --output environment_check.json
```

同名環境がある場合は削除せず、社内で内容を確認してください。診断は環境とGUI生成、日本語OCRの利用可否を確認し、本番台帳や保存PDFを変更しません。社内承認自体はプログラムでは判定できません。

ソースから起動する場合は、承認済み環境を有効にしたPromptで `run_windows.bat` を実行します。環境診断に成功してから起動し、別のPythonへ自動で切り替えません。画像OCRには社内で許可されたPowerShell実行が必要です。実行中にOCRを利用できなくなっても原本保存と、読み取り失敗・未処理の表示を分けて扱います。

## 将来のEXE作成と配布

今回の更新ではビルドを実行していません。社内で作成する際は「社内PCでのEXE作成と評価.md」に沿って、承認済み環境で `build_windows.bat` を実行します。

環境診断、全自動テスト、PyInstallerでの作成、配布ZIPの検査を順番に行い、失敗時は停止します。毎回 `build_runs` に日時と識別番号の付いた出力先を作り、以前のEXEを流用しません。未完了ZIPを成功結果として表示しません。ZIP作成の成功と、配布先でのEXE起動確認は別です。

作成後はZIPをすべて展開し、`KanpoChecker.exe` と同じ場所の `run_evaluation.bat` を使います。`_internal` を含むフォルダー全体が必要です。Python未導入の社内Windows PCでも、起動、画像OCR、原文表示、確認結果の保存と再起動、CSV、バックアップを実機確認してください。ソフト配布や署名に社内手続きがある場合はそれに従ってください。

## 保存先と復元

通常起動は `%LOCALAPPDATA%\KanpoChecker`、評価用ランチャーは `%LOCALAPPDATA%\KanpoChecker-Evaluation` を使います。評価用にも前回のデータが残ります。「保存先を開く」で実際の場所を確認できます。同じ保存先での同時起動は防止します。

主な保存内容は `kanpo.sqlite3`（台帳、文書とページの状態、OCRと印、確認履歴、日次取得記録）、`pdf`（原文）、`backups` です。`download_staging` に受信PDFが残る場合は原本登録に失敗しています。これは未登録のため、完全バックアップに含まれるとは限りません。手動対応が終わるまで保存先ごと保持してください。

完全バックアップZIPには整合したデータベース、登録された全原文PDF、ハッシュ一覧が入ります。原本が欠けたり変更されていたりすると成功扱いにしません。DB単体のバックアップには原文PDFがありません。

復元時はアプリを終了し、現在の保存先全体を別の場所へ退避します。バックアップZIPを空の作業フォルダーへ展開し、`kanpo.sqlite3` と `pdf` を一式で、復元対象の保存先へ配置します。評価用と通常用を取り違えないでください。起動後に台帳件数、文書・ページ、確認履歴、原文を確認します。既存データへの継ぎ足しやアプリ内の自動復元は行いません。

台帳・原文・OCR本文を外部OCRサービスへ送信しません。実台帳、結果CSV、バックアップは社内の許可された場所で保管してください。

## 評価の範囲と残る確認

旧0.6の基準結果では、追加3号の22代表ページから転記した26法人名中20件、公告タイトル18件中14件、節見出し1件中1件を検出しました。原文から作った検証用台帳での結果で、実台帳は使用していません。**これは変更前の過去の基準値であり、0.7の最新精度ではありません。** その3号を改善にも使用しており、未知の号を評価した精度でもありません。

0.7では、既存の4方向OCR結果と機械が選んだ領域の実OCRを用い、同じ26法人標本で完全一致22件・近似候補2件・未候補2件となりました。その解析結果を原本保存・ページ処理・台帳照合・再起動・CSV出力へ接続し、同じ候補が保存・出力されることも確認しました。画面の確認手順は別途、架空の検証データで確認しています。近似候補は同一法人の確定ではありません。実台帳や全文字の正解率、公告の網羅性を測ったものではありません。未候補のうち印も出ない箇所があり、印なしを正確性の保証にはできません。

旧版では本紙1797号の8～32ページの原本保存・OCR・確認履歴・バックアップの通し確認、および追加3号の公告開始12・8・1ページを候補化する確認を行いました。これも当該標本での検証で、公告の網羅性や文字の完全な正確性を保証しません。

0.7の方向別補足、要確認の印、局所再読取による実務上の精度は、代表的な別の号と実台帳で評価が必要です。標本での改善があっても全官報で同じ精度とは扱いません。候補なし・印なし・処理完了だけで原文確認を省略しないでください。

公告単位への完全分割、会社住所や資本金・金額・日付の構造化抽出、法人番号照合、電子署名検証は未実装です。公式PDFの当日取得は実通信で4号の保存まで確認しました。社内承認環境でのEXE作成、配布先起動、社内ネットワークからの取得、実台帳の精度評価は残っています。今回の実取得試験ではOCRを無効にしており、最新0.7での1号全体の実OCR通し確認など、取得以外の残る検証は「0.7の実装と検証.md」を参照してください。
